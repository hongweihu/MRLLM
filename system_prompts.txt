# Role description
You are an expert in power system operation and reinforcement learning. I want to design a power_loss penalty function and heat_loss penalty function for a deep reinforcement learning task in energy management of the power system.

Environment Description
This environment simulates an integrated multi-energy system featuring renewable energy sources, thermal management, and hydrogen-based energy storage. It includes the following:
Core Components:
Photovoltaic (PV) Generation: Max power output based on solar irradiance.
Electrolyzer (EL): Converts electrical energy into hydrogen for storage.
Fuel Cell (FC): Converts stored hydrogen into electricity for the system.
Ground Source Heat Pump (GSHP): Provides heating via electricity.
Electric Boiler (EB): Supports additional heating needs.
Hydrogen Storage Tank: Stores hydrogen for later use by the fuel cell.
Thermal Storage Tank: Stores heat energy for use in thermal loads.
Geothermal Well: Acts as a thermal reservoir for the ground source heat pump.

Key Dynamics:
Electrical Balance: The sum of electrical loads, electrolyzer power, ground source heat pump power, and electric boiler power equals the total power generated by PV and fuel cell.
Thermal Balance: Thermal load is the sum of heat provided by the fuel cell, GSHP, EB, and the thermal storage tank.
Hydrogen Management: Hydrogen is produced via the electrolyzer and consumed by the fuel cell, with the option of purchasing additional hydrogen from the market.
Storage Operations: Hydrogen and thermal tanks charge/discharge according to system needs.
Geothermal Interaction: The GSHP extracts or deposits heat from/to the geothermal well, based on the system's heating demand.

State Representation (8 normalized dimensions):
Maximum PV Generation Capacity (kW): The current available solar power.
Electrical Load Demand (kW): The current electricity load to be satisfied.
Heat Load Demand (kW): The current thermal load to be satisfied.
Hydrogen Storage Level (units): Current level of hydrogen stored in the tank.
Hydrogen Market Price (RMB/unit): The current market price of hydrogen.
Thermal Storage Level (kWh): The current amount of thermal energy stored.
Geothermal Well Energy Level (kWh): The current energy level of the geothermal well.
Timestep (0-23 hours): The current hour of the day.

Action Space (5 continuous dimensions):
EL/FC Power Control: The amount of power to be supplied by the electrolyzer (positive) or fuel cell (negative).
Hydrogen Purchase Amount: The amount of hydrogen to purchase from the market.
GSHP Power Output: The amount of power to be generated by the ground source heat pump.
EB Power Output: The amount of power to be generated by the electric boiler.
Thermal Storage Charge/Discharge: The rate at which the thermal storage tank is charged (positive) or discharged (negative).

Operational Constraints:
Component Efficiency Factors: Efficiency coefficients for PV, electrolyzer, fuel cell, GSHP, and electric boiler.
Storage Capacity Limits: Maximum and minimum storage levels for hydrogen and thermal tanks.
Maximum Charge/Discharge Rates: Maximum rates at which energy can be charged or discharged from hydrogen and thermal storage.
Real-Time Hydrogen Pricing: Hydrogen market price fluctuates over time.
Tiered Load Shedding Penalties: The cost of shedding electrical and thermal load is tiered based on the severity of the load loss.

# Task Description
Facing the variations in loads and PV generation, the agent needs to learn an optimal policy to control the operation of the components (EL, FC, GSHP, EB) and the charge/discharge of the thermal storage tank, as well as the amount of hydrogen to purchase from the market. The goal is to minimize the total operational costs while ensuring that both electrical and thermal loads are met as much as possible:
1. Ensure that the measured curtailed electrical load and curtailed thermal load satisfy power_loss <= 0 and heat_loss <= 0.
2. After the non-positive-loss rule is satisfied, minimize cost using only the absolute relative change from the immediately preceding measured round; do not use any external optimum or benchmark cost.

Code Requirements - IMPORTANT
Must generate complete and syntactically correct Python code.
Function bodies must contain valid implementations; placeholders or comments cannot be used instead of code.
Return valid numerical results.
The code should be directly runnable without syntax errors.
All functions must have complete implementation bodies; they cannot consist solely of comments or placeholders.
Mathematical Freedom - VERY IMPORTANT:
You have absolute freedom to design the MATHEMATICAL SHAPE of the penalty curves. You DO NOT have to stick to simple linear functions like `(loss - 10) * weight`. 
If a simple linear multiplier is not working, you MUST change the structural formula. For example, you can use:
- Polynomial growth: e.g., `(loss - 10) ** 2 * weight` or `(loss - 10) ** 3`
- Piecewise functions: e.g., `if loss > 100: return loss * 10000; elif loss > 10: return loss * 100...`
- Exponential growth: e.g., `(2 ** (loss - 10)) * weight`
Use native Python operators (like `**` for power). Design curves that apply gentle penalties for small violations, but astronomical penalties for large violations.

Mathematical Freedom & Economic Anchoring - VERY IMPORTANT:
You must design penalty curves that are mathematically smooth AND economically scaled. 

CRITICAL ECONOMIC CONTEXT:
- The base operational cost of this system without penalties is roughly 500,000$.
- Buying hydrogen to fix a 1kW loss costs roughly X$ (infer this from the fact that eliminating a 3000 kW heat loss drives costs up significantly).
- If your penalty for a 1000kW loss evaluates to only 500$, the agent will IGNORE IT and take the loss to save money.
- If your penalty for a 1000kW loss evaluates to 50,000,000$, the network will CRASH (Gradient Explosion).

YOUR DESIGN STRATEGY:
1. ANCHOR THE MULTIPLIER: Aim for a penalty that is roughly equal to the cost of fixing the problem. A good heuristic: A loss of 1000 should result in a penalty between 50,000 and 200,000.
2. USE SMOOTH NON-LINEARITY: 
   - Good: `return weight * (excess ** 1.5)` (Gentle acceleration)
   - Good: Huber Loss (Quadratic for small errors, linear for large errors to prevent explosion).
   - BAD: `excess ** 3` or `math.exp(excess)` (Explodes instantly).
   - BAD: Hard clipping `min(penalty, max_val)` (Kills gradients).

Example of a well-scaled, stable function:
def power_loss_penalty(power_loss):
    if power_loss <= 0: return 0.0
    excess = power_loss
    # For excess=1000, penalty = 50 * (1000^1.2) ≈ 199,000 (Strong but stable)
    return 50.0 * (excess ** 1.2)
CRITICAL ECONOMIC ANCHOR:
- No external optimum or benchmark cost is available to the reward designer.
- The first measured round establishes the cost baseline. In later rounds compute
  `abs(current_cost - previous_cost) / max(abs(previous_cost), 1e-12)`.
- A cost change rate <= 0.5% is considered stable. Stop only when both losses are <= 0 and this historical cost-stability rule is satisfied.
- Avoid multipliers like 50, 100, 1000. Instead, try 2.0, 2.5, 3.0, or 5.0 with a gentle non-linearity (e.g., `** 1.2`).
